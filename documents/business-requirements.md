# Food Cost — Business Requirements

> แอปจัดการต้นทุนและวางแผนการซื้อวัตถุดิบสำหรับร้านอาหาร delivery ของเรา  
> **Stack:** Vite · Vue 3 · TypeScript · Tailwind CSS · Supabase · Vercel

---

## 1. ภาพรวมธุรกิจ (Business Overview)

ร้านอาหาร delivery ต้องการระบบหลังบ้านที่ช่วย **คำนวณต้นทุน–กำไรต่อเมนู** และ **วางแผนการซื้อวัตถุดิบ** จากยอดขายเป้าหมาย โดยไม่ต้องแปลงหน่วย — ผู้ใช้กำหนดหน่วยและราคาเองตั้งแต่ต้น แล้วระบบคำนวณต่อจากนั้น

**เป้าหมายหลัก**

| เป้าหมาย | คำอธิบาย |
|----------|----------|
| รู้ต้นทุนจริงต่อหน่วยขาย | จากสูตร (วัตถุดิบ + add-on) + บรรจุภัณฑ์ + ต้นทุนคงที่ + LINE MAN 30% — รองรับ **กล่อง** และ **มัดถุง** |
| รู้กำไรสุทธิก่อนตั้งราคาขาย | ป้อนราคาขาย → หักค่าบริการ 30% → ได้กำไรหลังต้นทุนและ % margin |
| วางแผนซื้อของล่วงหน้า | จากยอดเป้าหมาย × จำนวนวัน → รายการซื้อและงบรวม |
| ข้อมูลกลาง ปลอดภัย | Login คนเดียว (เจ้าของร้าน) — ป้องกันไม่ให้คนอื่นเข้าถึง |

## 3. ขอบเขตฟีเจอร์หลัก (Core Features)

### 3.1 จัดการวัตถุดิบ (Ingredients)

**ความต้องการ**

- เพิ่ม / แก้ไข / ลบ / ค้นหาวัตถุดิบ
- แต่ละวัตถุดิบมี:
  - **ชื่อ** (เช่น หมูสับ, ผักกาดขาว)
  - **หน่วย** (เช่น kg, กำ, ลูก, ถุง) — ผู้ใช้กำหนดเอง ไม่บังคับแปลงหน่วย
  - **ราคาต่อหน่วย** (บาท/หน่วย)
  - หมวดหมู่, ซัพพลายเออร์, หมายเหตุ
- **ประวัติการเปลี่ยนราคา** — บันทึกและดูย้อนหลังว่าราคาเปลี่ยนเมื่อไหร่ กระทบ margin อย่างไร

**กฎทางธุรกิจ**

- หน่วยของวัตถุดิบคือหน่วยเดียวที่ใช้ในสูตร — ถ้าซื้อเป็น pack ให้ผู้ใช้แปลงเป็นราคาต่อหน่วยที่ใช้ในครัวเองก่อนบันทึก

---

### 3.1.1 จัดการบรรจุภัณฑ์ (Packaging)

**ความต้องการ**

- เพิ่ม / แก้ไข / ลบ / ค้นหารายการบรรจุภัณฑ์ (โครงสร้างเดียวกับวัตถุดิบ — ชื่อ, หน่วย, ราคาต่อหน่วย)
- รายการมาตรฐาน:
  - **กล่องข้าว** (หน่วย: ใบ / กล่อง) — ใช้กับเมนูแบบ **กล่อง**
  - **ช้อนพลาสติก** (หน่วย: ชิ้น / อัน) — ใช้กับเมนูแบบ **กล่อง** เท่านั้น
  - **ถุงใส่กล่องข้าว** (หน่วย: ใบ / ถุง) — ใช้กับเมนูแบบ **กล่อง**
  - **ถุงมัด** (หน่วย: ใบ / ถุง) — ใช้กับเมนูแบบ **มัดถุง** (กับข้าว)
- แต่ละเมนูกำหนดใน BOM ว่าใช้บรรจุภัณฑ์อะไรกี่หน่วยต่อ 1 หน่วยขาย — ขึ้นกับ **ประเภทหน่วยขาย** ของเมนู

**กฎทางธุรกิจ (ตกลงแล้ว)**

| ประเภทหน่วยขาย | บรรจุภัณฑ์ที่ใช้ |
|----------------|------------------|
| **กล่อง** (ราดข้าว) | กล่อง + ช้อน + ถุงใส่กล่อง |
| **มัดถุง** (กับข้าว) | ถุงมัด — **ไม่มีช้อน, ไม่มีกล่อง** |

- บรรจุภัณฑ์ใช้หน่วยเดียวกับที่บันทึก — ไม่แปลงหน่วย
- ระบบ **preset บรรจุภัณฑ์ตามประเภทหน่วยขาย** — เลือก “กล่อง” แล้วเติม BOM ให้อัตโนมัติ, เลือก “มัดถุง” แล้วใส่แค่ถุงมัด

---

### 3.1.2 ช่องทางขาย / ค่าบริการแพลตฟอร์ม (Platform Fee)

**ความต้องการ**

- ร้านขายผ่าน **LINE MAN** เท่านั้น — ระบบหัก **ค่าบริการ 30%** ออกจากราคาขายเมื่อคำนวณกำไร
- **อัตราค่าบริการ: 30% คงที่ทุกเมนู** (ไม่มีโปรโมชันอัตราต่างกัน)
- ตั้งค่าอัตราได้ที่ระดับร้าน (settings) — default = 30% กรณี LINE MAN ปรับในอนาคต

**กฎทางธุรกิจ**

- ค่าบริการคิดจาก **ราคาขายเต็ม** (ก่อนหักต้นทุนวัตถุดิบ) — สูตร: `ค่าบริการ = ราคาขาย × 30%`
- **รายได้ที่ร้านได้รับ** = ราคาขาย − ค่าบริการ = ราคาขาย × 70%
- ค่าบริการแพลตฟอร์ม **ไม่** ส่งผลต่อแผนซื้อวัตถุดิบ (ซื้อของตามจำนวนหน่วยขาย ไม่เกี่ยวกับ % แพลตฟอร์ม)

---

### 3.2 จัดการเมนู / สินค้า (Menu Items)

**ความต้องการ**

- เพิ่ม / แก้ไข / ลบ / ค้นหาเมนู
- แต่ละเมนูมี:
  - **ชื่อเมนู** (เช่น ข้าวผัดหมู, กะเพราหมูสับ)
  - **ประเภทหน่วยขาย** — `กล่อง` (ราดข้าว) หรือ `มัดถุง` (กับข้าว)
  - **รายการสูตร (BOM)** — วัตถุดิบ + บรรจุภัณฑ์ ต่อ 1 หน่วยขาย
  - **เมนูพ่วง (Add-ons)** — เมนูอื่นที่ขายร่วมกันในคำสั่งเดียว (เช่น กะเพราหมูสับ **พ่วงไข่ดาว**) — รวมต้นทุนวัตถุดิบของ add-on เข้าในต้นทุนเมนูหลัก
  - **ราคาขาย** (บาท) — ราคารวมที่ลูกค้าจ่าย (รวม add-on ถ้าขายเป็นชุด)
  - หมวดหมู่, สถานะ (ขายอยู่ / หยุดชั่วคราว), รูปภาพ

**กฎทางธุรกิจ (ตกลงแล้ว)**

| ประเภท | ตัวอย่าง | หน่วยนับ |
|--------|----------|----------|
| **กล่อง** | ข้าวราดหน้า, ข้าวผัด | กล่อง |
| **มัดถุง** | กะเพรา, ผัดไทย (กับข้าว) | มัด |

- ปริมาณในสูตรต้องใช้ **หน่วยเดียวกับ** ที่กำหนดในวัตถุดิบ (เช่น 0.1 kg, 0.5 กำ)
- ระบบ **ไม่** แปลงหน่วยระหว่าง kg ↔ กำ
- **เมนูพ่วง** — อ้างอิงเมนู add-on ที่มีสูตรอยู่แล้ว (เช่น ไข่ดาว) แล้วดึง BOM มารวม; หรือใส่สูตร add-on ตรงๆ ในเมนูหลักก็ได้
- บรรจุภัณฑ์ของเมนูหลักตามประเภทหน่วยขาย; add-on ที่เป็นแค่วัตถุดิบ (เช่น ไข่ดาว) ไม่เพิ่มบรรจุภัณฑ์แยก ยกเว้น add-on เป็นเมนูมัดถุงแยก

### 3.3 คำนวณต้นทุนและกำไรต่อเมนู (Cost & Profit per Menu)

**ความต้องการ**

เมื่อกำหนดสูตรและราคาวัตถุดิบแล้ว ระบบคำนวณอัตโนมัติ:

| ตัวชี้วัด | สูตร |
|----------|------|
| **ต้นทุนวัตถุดิบต่อ 1 หน่วยขาย** | Σ (ปริมาณ × ราคา) ของวัตถุดิบใน BOM หลัก + **เมนูพ่วง (add-ons)** |
| **ต้นทุนบรรจุภัณฑ์ต่อ 1 หน่วยขาย** | Σ (ปริมาณ × ราคา) ตามประเภทหน่วยขาย (กล่อง vs มัดถุง) |
| **ต้นทุนคงที่ต่อหน่วยขาย** | ค่าแก๊ส + ไฟฟ้า + แรง (flat rate ต่อหน่วย — ตั้งค่าแยกกล่อง/มัดถุงได้) |
| **ต้นทุนรวมต่อ 1 หน่วยขาย** | ต้นทุนวัตถุดิบ + ต้นทุนบรรจุภัณฑ์ + ต้นทุนคงที่ |
| **ค่าบริการ LINE MAN (30%)** | ราคาขาย × 0.30 |
| **รายได้หลังหักแพลตฟอร์ม** | ราคาขาย − ค่าบริการ (= ราคาขาย × 0.70) |
| **กำไรสุทธิ (บาท)** | รายได้หลังหักแพลตฟอร์ม − ต้นทุนรวม |
| **% กำไรสุทธิ (Net Margin)** | (กำไรสุทธิ ÷ ราคาขาย) × 100 |
| **% ต้นทุนรวม (Total Cost %)** | (ต้นทุนรวม + ค่าบริการ) ÷ ราคาขาย × 100 — ดูภาพรวมว่าเหลือกำไรเท่าไหร่ |

**UI ที่ต้องการ**

- **ตารางเปรียบเทียบเมนูทั้งหมด (Menu Profit Comparison)** — หน้าหลักหรือหน้าเฉพาะ แสดง **ทุกเมนูที่ขายอยู่** ในแถวเดียวกัน เพื่อเปรียบเทียบว่าเมนูไหนกำไรดีที่สุด
  - คอลัมน์: ชื่อเมนู | ประเภท (กล่อง/มัดถุง) | ราคาขาย | ต้นทุนรวม | ค่าบริการ LINE MAN | กำไรสุทธิ (บาท) | % กำไรสุทธิ
  - **เรียงลำดับได้** — default เรียงตามกำไรสุทธิ (บาท) จากมากไปน้อย หรือเรียงตาม % margin
  - **ไฮไลต์** — เมนูกำไรสูงสุด / ต่ำสุด (หรือ margin ติดลบ) ให้เห็นชัด
  - คลิกแถว → ไปหน้ารายละเอียดเมนู (breakdown เต็ม)
  - กรอง: เฉพาะเมนูที่ active, ตามหมวดหมู่, ตามประเภทหน่วยขาย
- หน้ารายละเอียดเมนู: ตาราง breakdown แยก **วัตถุดิบ**, **บรรจุภัณฑ์**, **ต้นทุนคงที่**, **ค่าบริการแพลตฟอร์ม** → ต้นทุน/หักแต่ละรายการ → **กำไรสุทธิ**
- ปรับราคาขาย (what-if): เปลี่ยนราคาขายแล้วเห็นกำไรสุทธิเปลี่ยนทันที (ตารางเปรียบเทียบอัปเดตตาม)
- **What-if ราคาวัตถุดิบ** — จำลองว่าวัตถุดิบแพงขึ้น X% แล้วดูว่าเมนูไหน margin ตก
- **เป้า margin %** — ตั้งเป้า (เช่น ≥ 30%) แล้วเตือนเมนูที่ต่ำกว่าเป้า / ติดลบ
- แนะนำราคาขายที่ควรตั้งจากเป้า margin (คำนึงค่าบริการแพลตฟอร์มด้วย)

**ตัวอย่าง**

- ราคาขาย 100 บาท (กะเพราหมูสับ + ไข่ดาว), ต้นทุนรวม 35 บาท (รวมไข่ดาวใน BOM)  
- ค่าบริการ LINE MAN = 100 × 30% = **30 บาท**  
- รายได้หลังหัก = 100 − 30 = **70 บาท**  
- กำไรสุทธิ = 70 − 35 = **35 บาท** (Net Margin 35%)

**หมายเหตุ:** คำนวณครบ **ต้นทุนวัตถุดิบ + บรรจุภัณฑ์ + ต้นทุนคงที่ + ค่าบริการแพลตฟอร์ม (LINE MAN 30%)**

### 3.4 วางแผนการซื้อวัตถุดิบ (Purchase Planning)

**ความต้องการ**

ผู้ใช้กำหนด:

1. **ยอดเป้าหมายขาย** — จำนวนหน่วยขายต่อเมนู (เช่น ข้าวผัดหมู 50 กล่อง, กะเพรา 30 มัด)
2. **จำนวนวันที่เตรียมของ** — เช่น 1 วัน (ซื้อสด) หรือ 5 วัน (ซื้อมาทีเดียว)

ระบบคำนวณ:

| ผลลัพธ์ | สูตร |
|---------|------|
| **ปริมาณที่ต้องซื้อ (วัตถุดิบ + บรรจุภัณฑ์)** | สำหรับแต่ละรายการ: Σ (ปริมาณในสูตร × จำนวนขายของเมนูนั้น) × **จำนวนวัน** |
| **ต้นทุนรวมการซื้อ** | Σ (ปริมาณที่ต้องซื้อ × ราคาต่อหน่วย) — รวมทั้งวัตถุดิบและบรรจุภัณฑ์ |

**UI ที่ต้องการ**

- เลือกเมนู + ใส่จำนวนหน่วยขาย (กล่อง / มัด) — รองรับหลายเมนูพร้อมกัน
- ช่อง **จำนวนวัน** (default = 1)
- ตารางสรุป: รายการ (วัตถุดิบ/บรรจุภัณฑ์) | ประเภท | หน่วย | ปริมาณรวม | ราคา/หน่วย | ราคารวม
- แถว **รวมงบซื้อทั้งหมด**
- บันทึกแผน / โหลด **เทมเพลตแผนซื้อประจำ** (เช่น แผน “วันจันทร์”)
- export PDF หรือ CSV สำหรับไปซื้อของ
- **บันทึกยอดขายจริง vs เป้า** — เปรียบเทียบแผนซื้อกับของที่ใช้จริง

**ตัวอย่าง**

- เป้า: ข้าวผัดหมู 50 กล่อง/วัน, เตรียม 5 วัน  
- หมูในสูตร 0.1 kg/กล่อง → ต้องใช้ 0.1 × 50 × 5 = **25 kg**  
- กล่อง 1 ใบ/กล่อง → ต้องใช้ 1 × 50 × 5 = **250 ใบ** (ช้อน, ถุง คำนวณแบบเดียวกัน)

## 4. ฟีเจอร์อื่นๆ (Additional Features)

| ฟีเจอร์ | รายละเอียด |
|---------|------------|
| **หมวดหมู่เมนูและวัตถุดิบ** | จัดกลุ่ม (อาหารจานเดียว, เครื่องดื่ม ฯลฯ) |

| **เป้า Food Cost %** | ตั้งเป้าระดับร้าน (เช่น ≤ 35%) แจ้งเตือนเมนูที่เกิน |
| **Promo / ชุด combo** | ขายเป็น set — รวมต้นทุนและกำไรหลายเมนู |
| **แจ้งเตือน** | วัตถุดิบที่ยังไม่ตั้งราคา, เมนู margin ติดลบ, เกินเป้า Food Cost % |

```
  -- เช่น กะเพราหมูสับ menu_item_id → addon ไข่ดาว quantity 1

recipe_lines (BOM)
  id, menu_item_id, ingredient_id, quantity_per_unit

combos
  id, name, selling_price, created_at

combo_items
  id, combo_id, menu_item_id, quantity

purchase_plans
  id, name, days, is_template?, created_at

purchase_plan_lines
  id, plan_id, menu_item_id, target_quantity

sales_records
  id, plan_id?, menu_item_id, target_qty, actual_qty, recorded_at
```

**การคำนวณ (ไม่เก็บใน DB เป็นหลัก — คำนวณ realtime)**

- `ingredient_cost` = sum(BOM หลัก) + sum(BOM ของ menu_addons ที่ผูกไว้)
- `packaging_cost` = sum(recipe_lines where type=packaging) — ตาม sale_unit_type
- `fixed_cost` = fixed_cost_box ถ้า sale_unit_type=box, fixed_cost_bag ถ้า bag
- `menu_cost` = ingredient_cost + packaging_cost + fixed_cost
- `platform_fee` = selling_price × (platform_fee_percent / 100)  // default 30%
- `net_revenue` = selling_price − platform_fee
- `net_profit` = net_revenue − menu_cost
- `purchase_qty(item)` = sum over menus(recipe_qty × target_qty × days) — รวมวัตถุดิบและบรรจุภัณฑ์

## 7. User Flow หลัก

### Flow A: ตั้งค่าครั้งแรก

1. Login  
2. ตั้งค่าร้าน — LINE MAN 30%, ต้นทุนคงที่ (แก๊ส/ไฟ/แรง) ต่อกล่องและต่อมัดถุง  
3. เพิ่มวัตถุดิบ + บรรจุภัณฑ์ + ราคา/หน่วย  
4. สร้างเมนู — เลือกประเภท (กล่อง/มัดถุง), ใส่สูตร, พ่วง add-on ถ้ามี (เช่น +ไข่ดาว)  
5. ตั้งราคาขาย → ดูต้นทุนและกำไรสุทธิ  

### Flow B: วางแผนซื้อของ

1. ไปหน้า “แผนซื้อของ”  
2. เลือกเมนู + จำนวนที่คาดขาย (กล่อง / มัด)  
3. ใส่จำนวนวัน (เช่น 5)  
4. ดูรายการวัตถุดิบและงบรวม → export/ไปซื้อ  

### Flow C: เปรียบเทียบกำไรระหว่างเมนู

1. เปิด **ตารางเปรียบเทียบเมนู** (หน้าแรกหลัง login หรือเมนูหลัก)  
2. ดูทุกเมนูเรียงตามกำไรสุทธิ — ระบุเมนูที่ margin ดี/แย่  
3. คลิกเมนูที่สนใจ → ดู breakdown หรือปรับราคาขาย  

### Flow D: ปรับราคาเมื่อวัตถุดิบแพงขึ้น

1. แก้ราคาวัตถุดิบ  
2. เปิดเมนูที่เกี่ยวข้อง → margin อัปเดตทันที  
3. ตัดสินใจปรับราคาขายหรือไม่
